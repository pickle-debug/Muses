# Muses：2–3 个工作日 Demo 规格与验收

版本：V0.2

日期：2026-08-23

目标：使用原生 SwiftUI 在开发者自有 iPhone 上跑通真实端到端链路

## 1. Demo 定义

本 Demo 不是视觉原型，而是具备真实模型调用、真实媒体下载、真实动态格式封装和真实相册保存能力的技术产品切片。

固定主流程：

`输入临时 Key → 上传 SKU 图 → AI 预填 → 确认事实 → 生图 → 图片审核 → AI 动态 → 动态审核 → 文案 → 动态格式封装 → 保存`

Demo 只回答四个问题：

1. 用户能否用足够简单的表单建立可信商品上下文？
2. 图片和 AI 动态是否保持商品关键特征？
3. iOS Live Photo 能否在目标 iPhone 保存、识别和用于小红书？
4. 用户是否认为最终内容值得实际发布？

## 2. 范围锁定

### 2.1 必须完成

- 原生 SwiftUI iOS 工程可在 iPhone 真机运行，Demo 最低支持 iOS 17。
- 使用 Swift 6、SwiftUI、PhotosUI、PhotoKit、AVFoundation、URLSession 和 Swift Concurrency；不依赖 React Native、Expo 或跨端运行时。
- 本地 JSON 配置固定 Endpoint、模型和协议映射。
- 用户输入由产品负责人单独发放的临时 API Key。
- 从系统相册选择 3–6 张商品实物图。
- AI 预填商品事实，用户可以修改和确认。
- 使用固定模板生成一张 3:4 图片。
- 图片商品一致性人工审核。
- 使用已审核图片生成一段 3–5 秒、720p、静音 AI 动态。
- 动态商品一致性人工审核。
- 生成 3 个标题、1 篇正文和 8–12 个话题。
- 生成并保存 Apple Live Photo，同时保存 MP4 和静态图。
- 失败状态可见；异步视频任务可恢复查询。
- 所有 SKU、任务和结果保存在当前 iPhone 本机。

### 2.2 明确不做

- 登录、注册、邀请码、云同步和团队协作。
- Android 客户端、Android Motion Photo 和双端工程；Android 兼容性验证移至四周 MVP Spike。
- 业务后端、服务端配置、服务端 Credits 和服务端任务队列。
- 抖音适配、小红书 OAuth、自动发布和帖子数据读取。
- 15 秒视频、多镜头、声音、字幕和视频编辑器。
- 多模板、自由提示词编辑、局部重绘和候选图对比。
- 自动埋点、分析后台和推送通知。
- 正式支付、订阅、充值和分佣。
- 根据当前 SwiftUI Demo 推导或承诺 Android 上传、发布能力。

## 3. 时间盒计划

时间盒从开发环境、签名和供应商接口均可用时开始计算。任何依赖未就绪都会影响 2–3 天目标。

### Day 1：真实生图链路

目标：在一台真机完成 `配置 → SKU → AI预填 → 生图 → 图片审核`。

- 初始化原生 SwiftUI App 工程，设置 iOS 17 Deployment Target。
- 使用 `PhotosPicker` 配置 iOS 相册选择和权限说明。
- 加载本地 `provider.config.json`。
- 实现临时 Key 输入、普通本地存储、测试连接和删除。
- 使用 Swift `Codable` 模型建立本地 SKU、商品快照、任务和资产数据结构；结构化数据优先保存到 Application Support。
- 完成极简商品输入与 AI 预填页面。
- 对接文本模型做商品事实抽取。
- 对接 `gpt-image-2` 生成一张图片。
- 完成图片审核页和失败重试。

Day 1 完成标准：真实商品图可以通过固定 Endpoint 生成一张可预览结果；App 不因切换页面丢失任务状态。

### Day 2：AI动态、文案和iOS实况

目标：在 iPhone 完成全链路。

- 对接异步视频创建和任务查询。
- 下载并本地保存 MP4。
- 完成动态预览和审核。
- 对接小红书文案生成。
- 编写 Swift `LivePhotoService`，按 Apple 资源配对要求写入 Photos。
- 完成保存结果页、复制文案和打开小红书。
- 覆盖 Key 无效、额度不足、任务失败、下载失败和权限拒绝。

Day 2 完成标准：一台 iPhone 成功保存可在系统相册长按播放的 Live Photo，且 MP4 和文案可用。

### Day 3：iOS 真机修整与发布验证

目标：SwiftUI Demo 在目标 iPhone 上可重复完成，失败后可恢复，不重复产生高成本任务。

- 测试 Photos 中的 Live Photo 标识、长按播放和 MP4/静态图保存。
- 测试小红书选择器、草稿和人工发布；记录发布后 iOS/Android 客户端观看结果。
- 检查低网速、切后台、恢复、删除项目和删除 Key。
- 检查 `scenePhase` 切换后的异步任务恢复与轮询续接。
- 完成下载失败、Live Photo 封装失败和权限拒绝的降级提示。
- 使用至少 2 个不同 SKU 做完整回归，避免模板只适配水杯。

Day 3 完成标准：目标 iPhone 连续完成真实链路，Live Photo、MP4、静态图和文案可用；任何失败均不静默重复提交生成任务。

## 4. 页面规格

### D-01 启动与临时配置

显示：

- Muses 开发代号。
- “本次测试会将所选商品素材发送到指定生成服务”的提示。
- 固定服务域名，只读展示。
- 临时 Key 输入框。
- 测试连接、保存、删除按钮。

规则：

- Endpoint 不允许用户编辑。
- Key 保存后默认掩码显示。
- Key 不允许复制回剪贴板。
- 测试连接不得触发高成本媒体任务。
- Key 无效时不得进入创作流程。

### D-02 新建商品

首屏只包含：

- 3–6 张商品图片。
- 商品名称。
- 一句话真实卖点。

交互：

- 图片支持多选、删除和重新排序。
- 不足 3 张时提示补充角度，但允许开发者调试模式继续。
- 点击“AI识别商品”前显示将发送的图片数量。

### D-03 商品事实确认

字段：

- 名称、类目、材质、规格/容量、主色、显著图案、包装文字。
- 目标人群。
- 1–3 个真实卖点。
- 禁止改变的特征。
- “不确定/不适用”。
- 素材及营销使用权确认。

规则：

- 每个 AI 字段显示“AI识别，待确认”。
- 用户修改后标记“用户确认”。
- 未确认关键特征不得开始生成。
- 表单默认展示摘要，低频字段在“更多商品信息”中展开。

### D-04 生成图片

固定配置摘要：

- 小红书。
- 真人手持生活方式。
- 3:4。
- 1 张。
- 当前模型名。

状态：

- 正在准备参考图。
- 正在提交。
- 正在生成。
- 正在下载。
- 待审核。
- 失败/已取消。

不得显示虚假精确倒计时，只显示已等待时间和供应商状态。

### D-05 图片审核

布局：商品参考图可横向浏览，生成图作为主图显示，支持放大。

审核项：

- 外形、颜色、图案、文字、材质和规格关系。
- 是否增加不存在的部件、赠品或效果。

操作：

- “商品一致，可以继续”。
- “有问题，重新生成”。

问题标签：外形改变、颜色错误、图案错误、文字错误、材质错误、增加物品、其他。选择后追加到下一版负面约束。

### D-06 生成与审核AI动态

输入为已审核图片，不允许选择未审核结果。

固定目标：

- 3–5 秒，具体值由 JSON 配置。
- 720p。
- 静音。
- 轻微自然动作和镜头运动。
- 商品本体不得形变，不新增文字。

视频审核沿用图片清单，并增加：

- 商品是否在运动中变形、融化或闪烁。
- 手与商品接触是否异常。
- 背景是否出现明显跳变。

审核失败只重做动态，不强制重做已通过的图片。

### D-07 文案结果

显示：

- 3 个可单选标题。
- 一篇可编辑正文。
- 8–12 个可删除的话题。
- “AI内容，请核对商品事实”提醒。

禁止默认生成虚构经历、虚假价格、疗效、权威背书和未经确认的用户评价。

### D-08 保存结果

iOS：

- 保存 Live Photo。
- 保存 MP4。
- 保存静态图。
- 复制选中标题、正文和话题。
- 打开小红书。

Demo 不显示 Android 动态照片入口。Android Motion Photo 属于四周 MVP 的独立兼容性 Spike，不得在 SwiftUI Demo 中展示为已支持能力。

### D-09 本地历史

内容：

- 商品缩略图、名称、当前阶段、最近更新时间。
- 生成中、待审核、已保存、失败。

操作：

- 继续任务。
- 查看结果。
- 删除项目。

删除项目时删除本地素材引用、生成结果和任务信息；不会撤销供应商已经完成的调用或费用。

## 5. 端到端验收场景

### E2E-01 iOS正常链路

Given 用户已输入有效临时 Key，并选择 3–6 张商品图，

When 用户确认 AI 预填商品事实并完成图片与动态审核，

Then 系统生成一张图片、一段 MP4、一套文案，并在系统相册中保存可播放的 Live Photo。

通过证据：

- Photos 中显示并可播放 Live Photo。
- 静态图、MP4均可查看。
- 选中的标题、正文、话题可以复制。
- App 重启后本地历史仍存在。

### E2E-02 iOS Live Photo 封装失败降级

Given 图片、MP4 和文案均已生成并通过审核，

When Live Photo 配对或写入 Photos 失败，

Then App 保留并允许保存静态图、MP4 与文案，明确提示实况封装失败，不把整个内容包标记为失败。

### E2E-03 图片失真返修

Given 生成图改变了商品图案，

When 用户选择“图案错误”并重新生成，

Then 新任务引用原商品快照，并在新提示词版本中追加图案保持约束。

### E2E-04 动态失真返修

Given 已审核图片正确，但 AI 动态中商品发生形变，

When 用户拒绝动态并重新生成，

Then 系统保留图片审核结果，只创建新动态任务。

### E2E-05 App中断恢复

Given 视频任务正在供应商侧运行，

When App 被关闭并重新打开，

Then 系统使用已保存的供应商任务 ID 查询原任务，不重新提交和扣费。

### E2E-06请求超时

Given 提交请求超时且无法确认供应商是否收到，

When 用户返回任务页，

Then 状态显示“提交结果未知”，优先使用幂等键或查询能力对账；不得自动连续重复提交。

### E2E-07 Key失效

Given 临时 Key 已过期、撤销或余额不足，

When 用户开始生成，

Then 系统显示可理解原因并返回配置页，不输出包含完整 Key 的错误信息。

### E2E-08权限拒绝

Given 用户拒绝相册读取或写入权限，

When 用户选择图片或保存结果，

Then 系统解释对应用途并提供打开系统设置的入口；已有生成结果不得丢失。

## 6. 错误状态与文案

| 错误码 | 用户文案 | 恢复动作 |
|---|---|---|
| `CONFIG_INVALID` | 当前生成配置不可用 | 检查开发配置 |
| `API_KEY_INVALID` | 测试密钥无效或已过期 | 重新输入密钥 |
| `API_QUOTA_EXHAUSTED` | 当前测试额度已用完 | 联系测试负责人 |
| `PHOTO_PERMISSION_DENIED` | 需要相册权限才能选择商品图 | 打开系统设置 |
| `SAVE_PERMISSION_DENIED` | 需要照片写入权限才能保存结果 | 打开系统设置 |
| `PRODUCT_FACT_REQUIRED` | 请先确认商品关键信息 | 返回商品确认 |
| `IMAGE_GENERATION_FAILED` | 图片生成失败 | 查看原因并重试 |
| `VIDEO_STATUS_UNKNOWN` | 暂时无法确认动态任务状态 | 稍后继续查询 |
| `VIDEO_GENERATION_FAILED` | AI动态生成失败，图片仍已保留 | 重试动态 |
| `ASSET_DOWNLOAD_FAILED` | 结果下载失败 | 重新下载，不重复生成 |
| `REVIEW_REQUIRED` | 请先确认商品没有明显失真 | 进入审核 |
| `LIVE_PHOTO_PACKAGE_FAILED` | 实况照片生成失败，MP4仍可保存 | 重试封装/保存MP4 |

## 7. Demo配置要求

所有供应商差异必须集中在一个随 App 打包的 JSON 中。用户不能在界面修改 Endpoint 和模型；开发者通过修改 JSON 并重新构建来切换。

配置至少包含：

- 固定 Endpoint。
- 文本、图片、视频模型名。
- 文本、图片、视频请求路径。
- 视频创建、查询、结果提取方式。
- 图片比例、输出数量。
- 视频秒数、分辨率和是否静音。
- 请求超时、轮询间隔和总等待上限。
- 供应商返回字段映射。

配置不允许包含实际 API Key。

## 8. 质量门

### 8.1 可进入内部演示

- 正常链路在开发者 iPhone 连续成功 3 次。
- 同一视频任务恢复查询不会产生第二个供应商任务。
- Live Photo 在系统相册中可播放。
- MP4 与静态图在 iPhone 相册保存成功。
- 所有失败场景均不会显示完整 Key。

### 8.2 可交给3–5名用户

- 至少 3 名目标内测用户具备 iPhone；Android 用户不进入本轮 App 交付名单。
- 单用户临时 Key 已设置费用、并发和有效期限制。
- 设置页可以删除 Key，本地项目可以删除。
- 隐私提示说明素材会发送至指定供应商。
- 每次高成本调用前用户有明确动作，不在后台自动生成。
- 已知不兼容和降级路径已经写入内测说明。
