# Muses：三类素材生成与销售跟进功能逻辑

日期：2026-09-11

状态：Q39—Q43 已确认首版主流程和范围，可据此安排开发。商业效果待真实试用验证；本文不是代码完成声明。

## 1. 最新产品决定

用户在 Q39 明确要求：提供静态图、Live 动态图、视频三种生成工具，商户自己选择生成哪种素材并发布，产品继续跟进和分析数据。

因此：

- 核心功能是三类素材制作、发布跟进与分析。
- 商户无需先参加实验，也无需成对生成两种素材，才能正常使用产品。
- “同一杯子 Live 相对静态图是否提升转化”是一个可选实验案例；实验基线由参与实验的商户设置，不能成为软件立项和开发的前置问题。
- 软件以 SKU 和内容版本连接生成与经营反馈；模型供应商与算法细节不进入商户的必要操作。
- 初期可以人工登记发布信息和指标，已由 Q37 确认。自动同步需要真实权限与数据验证。

Q40 进一步明确的主流程：相册选几张商品图，自动建立 SKU，用户可编辑商品名称等资料；进入商品后由用户手动发起一批素材生成；支持时经官方账号授权后自动发布小红书，不支持时人工发布并回填链接；持续跟进数据，优化该商品下一次内容。此回答明确了业务流程，并没有新增多镜头视频、配音或字幕要求。

Q41—Q43 最终收敛（用户写的 Q52 按 Q42 理解）：

- 一次从相册导入一个 SKU，多商品批量导入作为后续能力。
- 一批素材属于同一个 SKU，用户自由选择生成一种、多种或全部三种，分别设置数量。
- **首版只做用户自行到小红书发布并回填链接。OAuth 和自动发布优先级降低，不进入首轮开发，也不需要先做接口适配或授权占位页面。**
- 这些选择已确认，下一步应进入任务拆分与实现安排，不重复要求用户批准同一条流程。

## 2. 商户完整操作

1. 在“我的商品”点击从相册添加，选择同一个商品的几张参考图。
2. 系统先保存本地商品草稿和参考图，分配内部唯一标识；自动识别并预填名称、可见规格、颜色等。用户查看并修改后进入商品详情。
3. 用户点击“生成素材”，选择静态 / Live / 视频及各自数量，可采用建议场景，也可手动写创作要求；查看预计费用后发起批量任务。
4. 在商品素材库看到逐项进度、成功结果和失败原因，挑选结果、提出修改或只重试失败项。
5. 从审核后的素材中组合内容，编辑标题正文，保存素材、复制文案，再自行到小红书完成发布。
6. 回填真实笔记链接、账号标记和发布时间。每个帖子关联最终使用的素材与文案；不能把打开小红书当作发布成功。
7. 首版人工跟进数据。商品页展示历史素材、帖子、销售趋势、成本与比较；自动同步后续按实际权限接入。
8. 系统提出下一次内容建议及依据，用户点击采用后预填新批次，修改并再次手动发起生成。

创建和发布不以销售数据齐全为条件。用户可以先完成素材任务，稍后登记帖子和指标。

### 从相册自动建 SKU

- Q41 已确认首版“一次选图属于同一个商品”，入口提示选择该商品多个角度；不自动分组或批量建立多个商品。
- 内部商品 ID 自动分配。商户已有 SKU 编号可后补；本地建商品不代表已在小红书创建商品、取得商品链接或上架。
- 名称及卖点不应成为保存草稿或发起商品识别的前置必填字段。识别失败时仍保留可编辑草稿，可使用临时名称；未证实的材质、容量、功效和价格留待确认。
- 不给每张照片创建一个 SKU。以后导入不同规格/颜色或多商品分组时，再明确分组和变体逻辑。
- 商品识别属于自动建档；图片/Live/视频素材生成仍由用户点击触发。编辑名称、查看商品或回填销售数据不会自动产生新的生成费用。

### 批量生成

- 一个批次隶属一个 SKU，包含所选素材类型、数量、创意要求及经确认的商品事实；可在同一批次生成多种类型，不强制每批都生成三种。
- 用户选择 3 张静态、2 个 Live、1 条视频时，记录为 6 个目标候选；为动态生成的中间图片或 Live 配对文件不另算一个目标候选，不以文件数量冒充完成数量。
- “一批素材”是候选集合，不等于要发布同样数量的帖子。用户可以将多张素材组合成一篇笔记，也可以仅发布部分结果。
- 建议首版默认小批量、允许调整数量，并展示预计费用；具体上限由真实模型成本与服务配额确定，不套用过去的日产量目标。
- 每个子任务独立保存状态、结果及费用；部分失败不丢掉成功素材，重开应用能恢复或继续查询任务。
- 取消批次应停止尚未提交的任务；已提交任务能否取消及是否计费取决于供应商，界面不承诺已经花费的费用可退。
- 批量可通过现有单次接口加受限并发执行，用户体验不依赖模型供应商提供批量 API。

### 产品里的四个主要页面

| 页面 | 用户看见什么 | 主要动作 |
| --- | --- | --- |
| 我的商品 | 从相册创建的商品及资料状态 | 新建、编辑、进入商品 |
| 商品详情与素材库 | 三类素材、批次任务、版本、近期帖子 | 发起生成、审核修改、选择素材 |
| 发布准备与记录 | 已选素材、标题正文、导出状态、实际笔记 | 保存素材、复制文案、手动发布、回填链接 |
| 商品效果 | 帖子表现、SKU 销售、成本、数据缺口及建议 | 更新数据、选择比较、采用下一次建议 |

这些是功能分区，可复用现有导航，不要求增加四个全新顶级 tab。

## 3. 三种生成工具

| 工具 | 用户输入 | 生成与交付 | 必须满足的行为 |
| --- | --- | --- | --- |
| 静态图 | SKU 事实、参考图、场景/卖点 | 生成图片，人工审核后可单独保存或配文发布 | 不要求创建视频任务、不产生动态生成费用 |
| Live 动态图 | 同一 SKU 下已审核的静态图，或先生成并确认静态图；轻动态意图 | 生成短动态并审核，再封装相配的 Live Photo 资源，按需提供 MP4 备份 | 用户从开始就知道目标是实况图；可复用已通过的静态素材 |
| 视频 | SKU 事实、已审核参考素材、视频目的/动作描述 | 生成视频并审核，独立导出 MP4；标题正文按需附带 | 可以在入口直接选择视频；不要求先保存 Live Photo，不能仅把 Live 导出按钮改名当作完整视频工具 |

### Live 与视频的共用和差异

共用商品事实、生成任务跟踪、成本记录、视频模型接入与人工审核。若已经有适合的媒体，只因切换导出格式不应重新生成或重复计费。

用户意图和输出分别记录：Live 偏向保留照片构图的轻动态；视频有独立的视频意图、动作描述、预览和 MP4 交付。两者能共用底层生成能力，不等于 UI 和业务规则只能合并成一个按钮。

**视频默认范围与未决项**：当前服务配置及原代码是短时单镜头、静音图生视频。Q40 没有新增多镜头、配音、字幕或较长成片要求；设计先沿用现有单镜头能力作为第一版默认，具体时长按实际配置展示。不能将这一默认说成用户明确选择，也不应因此阻塞相册建档、批量与发布数据流程；更复杂的成片要求出现时再调整范围。

### 版本与失败处理

- 已确认的商品事实可复用，每次创作绑定其当时的版本，避免后续改商品描述污染历史内容。
- 重新生成保留旧素材与修改原因；已发布内容记录不得自动切换到最新版本。
- 记录生成任务状态、失败与重试、供应商请求 ID、实际费用（若有）或明确标记的估算。
- 任务失败只重试失败步骤。已经通过的静态图不因动态失败而重做；相册保存失败不重复生成。
- 导出不等于发布；允许用户仅下载或放弃候选，不强制补写销售记录。

## 4. 发布关系：按实际笔记跟进

最低限度区分四个对象：

| 对象 | 记录内容 | 作用 |
| --- | --- | --- |
| 商品 | SKU、经确认的事实、来源素材 | 复用商品资料，汇总商品历史 |
| 内容版本 | 生成意图、实际资产、文案、父版本、审核与成本 | 追踪每次修改及商户采用情况 |
| 实际帖子 | 平台/账号/链接或 ID、发布时间、实际使用的资产与文案、内容形式、投流情况 | 指标归属于真实发布行为，而不是某个下载动作 |
| 指标快照 | 所属帖子或 SKU、统计范围、来源、累计截止时间与更新时间、可得指标 | 保留时间变化，支持比较且避免重复累加 |

一个内容版本可以用于多个帖子；一个帖子也可能使用多张静态图或混合静态/Live 素材。首版以“发布登记时选素材”为简化入口，不需要复杂分发系统。

用户生成了 Live 却最终发布静态图时，该帖子按实际发布记录分类；混合内容单独标识，不硬归为纯 Live。更正帖子链接时明确是在修正记录还是新增发布，不能把旧指标静默移到另一篇帖子。

### 后续可选：官方授权与发布分支

**Q43 已将本小节整体后置。仅保留研究记录，首轮不实现 OAuth、官方自动投稿或自动读数；不做空壳授权入口。**

分别确认账号身份/授权、图文发布、视频发布、Live 支持、商品挂载、内容指标和商品交易数据。一个接口或账号授权通过，不能推导所有能力都开放。

| 实际能力 | 软件行为 | 完成凭据 |
| --- | --- | --- |
| 官方直接发布适用于该账号及内容类型 | 用户审核并确认发布后提交，跟踪处理或审核状态 | 官方返回的已发布帖子 ID/状态；未提供公开链接时保留可用 ID |
| 只有官方分享 SDK / 拉起 App | 将已选素材和文案交给客户端，提示用户在小红书完成发布 | SDK 唤起/分享回调不自动当作公开发布，依据实际语义或用户回填确认 |
| 不具备适用发布能力 | 保存素材、复制文案、打开小红书，保留待回填记录 | 用户回填的实际笔记链接及确认 |

用户在 Q40 的“系统自动发布”按此前已确认的人审要求实现为：用户审核并确认发布后，系统完成技术提交。不会把整批未审核素材立即公开；若未来需要无逐次确认的定时/全自动发布，再单独明确账户、数量与授权边界。

- 发布权限不支持时，生成和手工发布仍可使用。
- 授权成功不自动发帖；选中的最终素材、文案和目标账号与发布记录关联。
- 提交超时先查询或标记“结果待确认”，不能立即重试或切到人工重复发同一篇。
- 官方接口返回“受理/审核中”时不能显示“已发布”。授权过期、权限撤销及不支持该素材类型有明确状态。
- 不能自动发布 Live 时保留原始实况素材的手动发布选择；不可静默转换成视频后仍按 Live 计入分析。
- 同一篇帖子即使含多份素材，指标只记录一次，不能把整篇订单复制到每份素材累加。

小红书具体能力的证据以官方文档及目标应用获批权限为准。店铺 OAuth、分享 SDK 与笔记服务端发布是不同路径；需要按当前接口与账号核实，不因“OAuth”这个名称预先实现无依据的发布承诺。

2026-09-11 官方资料核查记录：[小红书电商开放平台文档中心](https://open.xiaohongshu.com/document/developer/file/4)可读目录含自研商家、第三方服务商授权及商品/订单介绍。其自研授权正文说明应用与同主体/关联主体企业店的限制，并使用 `sellerId` 和店铺授权 token；该范围不可推广成第三方 SaaS 对所有类型店铺的统一规则。正文还含历史规则，生效状态须查控制台最新说明。公开读取未证实普通内容账号 OAuth、直接发布笔记、Live 支持、分享 SDK 或内容订单归因的具体接口；“未证实”不等于平台绝对不存在这些能力。

## 5. 人工回填与数据规则

### 首个可交付范围

- 登记真实笔记及所用素材。
- 人工填写平台后台已有的内容与交易指标，并记录数据截至时间、来源和口径。
- 商品页另记 SKU 同期销售与退款，用于经营趋势。
- 保存历史快照，允许更正；展示最新快照及其时间。

截图识别和批量表格导入可作为降低回填负担的后续小迭代；不假设用户已同意首版同时开发 OCR、所有文件格式及全部平台接口。

### 指标

- 内容：曝光、阅读/播放、点赞、收藏、评论、商品点击等，以平台实际字段为准。
- 交易：仅在有可靠来源时记录笔记关联的支付订单/买家数、金额、退款及其归因口径。
- SKU 经营：按统计窗口记录支付与退款金额、订单数量及必要成本。
- 制作：生成费用、失败重试费用、人工分钟数；可选记录商户实际支付的软件费用。

### 必须保持的数据性质

1. 未提供的数据是空值，不是 0。未填写订单不能解释为内容未成交。
2. 每次回填明确是累计值还是窗口增量；首版可只支持累计快照以减少歧义。累计快照不得逐次相加。
3. 笔记数据和 SKU 总销售分开。没有笔记归因证据时，不分摊 SKU 订单。
4. 计算率时标明分母、时间和归因范围；浏览、曝光、商品点击、买家不是同一个计数单位。
5. 仅有订单数与浏览次数时，最多展示“订单数/浏览次数”这一指定口径；不直接称为平台购买转化率或推断购买概率。
6. 退款可能晚于发布观察窗口，应保留更新及观察时点；未填履约成本时不能声称已经算出利润。
7. 同一笔记避免重复登记与重复统计。来自不同来源的指标不因数值相同或不同就静默合并。
8. 商家实际支付的软件价格与内部供应商成本分开，避免用创业者补贴后的算力价论证客户 ROI。

## 6. 数据分析与可选 A/B

### 日常跟进

商品页展示其真实帖子及素材类型、制作成本、数据新鲜度、已有表现和缺失数据。用户能回答：

- 哪些素材最后真的发布了，哪些持续被弃用？
- 哪个版本制作更快、返工更少？
- 同一商品的静态、Live、视频各获得怎样的可观测表现？
- 哪些比较有足够且可比的数据，哪些还不能解释？

不同素材类型的汇总只能描述观察，不按原始总订单把某种格式自动推荐给所有 SKU。

### 内容对照

商户选择已有内容作回顾比较，或在生成前建立实验，填写：问题、版本、主要变量、主指标及观察窗口。事后选择内容的比较应与预先设计实验区分。

比较时检查商品、账号、发布后时间跨度、付费/自然流量、价格与促销变化。无法匹配时显示差异及受限结论，不能凭“时间拉长”或“多发几篇”宣称随机 A/B。

初期结论分为：已观察到的差异、尚缺的数据、可尝试的下一步。随机分流、样本规划与统计判胜等需要独立验证实验条件后再开发，不作为普通素材生成的门槛。

### 下一次内容建议

从用户选定的素材和指标生成简短建议，引用具体证据。例如指出某版本制作成本更低但商品点击未变，建议再试另一种开头或场景。

建议默认由商户确认后创建新版本，保留父版本及改动意图。数据不足时可以建议取数或继续观察，不能补造订单、杜撰用户偏好或自动宣布销售提升。

下一轮优化以“可执行简报”交付：建议尝试的素材形式、场景/卖点、准备改动的一个主要变量及引用的帖子/数据。用户点击采用，只预填生成表单；再次确认数量与费用后才创建批次。应用无新数据时不声称已经学到新的用户偏好。

## 8. 实施顺序和验收

| 顺序 | 交付 | 验收 |
| --- | --- | --- |
| 1 | 相册选图自动建可编辑商品草稿 | 不必先填 SKU 和名称；识别失败保留草稿；仅创建商品不调用素材生成 |
| 2 | 三类素材选择与可恢复批量任务 | 用户点击后才生成；部分失败仅重试失败项；静态独立完成，Live 与视频分别交付 |
| 3 | 审核、手工发布准备、实际帖子关联及手工跟进 | 可组合素材；完整手工闭环可用；发布/累计数据不重复记录 |
| 4 | 数据口径、成本、退款、比较及下一次简报 | 缺失不算零；建议引用数据；采用建议预填表单，不自动花费或发布 |
| 后置 | 官方授权、发布及数据同步 | 后续根据试用需求与实际获批能力另行安排，不占首轮资源 |

重要验证场景：旧快照读取；自动建档失败与重复操作；编辑商品不会触发生成；批量部分失败与任务恢复；仅静态完成；Live/MP4 相册导出；没有帖子链接时保持待回填；同版本多帖；一帖多素材不重复订单；同帖重复登记；全空与零值；不同观察窗口；累计多次回填；退款后更正；无笔记交易归因时不展示虚假销售结论。
