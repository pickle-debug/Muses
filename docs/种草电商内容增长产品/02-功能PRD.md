# SKU 种草内容增长工作台：功能 PRD

版本：V0.1

日期：2026-08-21

状态：MVP 需求草案

## 1. 背景与目标

### 1.1 问题

用户已经使用生图工具为商品生成生活方式素材，但同一 SKU 需要反复输入近似提示词、多次生成和人工筛选。素材生成、图文/视频包装、平台发布和结果复盘彼此割裂。

### 1.2 产品目标

为抖音/小红书种草创作者提供一个以 SKU 为中心的内容工作流，使其能够：

1. 一次确认商品事实和参考素材。
2. 生成多个可比较的种草图片/短视频/轻动效版本。
3. 审核商品一致性、内容合规和平台规格。
4. 导出或经授权发布完整内容包。
5. 将内容表现、评论和销售信号连接到 SKU 与创意变量。
6. 在人工确认下启动下一轮单变量实验。

### 1.3 非目标

- MVP 不保证爆款或销售提升。
- MVP 不依赖抖音/小红书自动发布、评论和订单 API 才能成立。
- MVP 不做自动选品市场、实时库存同步或全自动投放。
- MVP 不允许系统在无人审核时自主发布内容。

## 2. 目标用户与用户故事

### 2.1 主要角色

- `Creator`：个体创作者/店主，可管理自己的 SKU、内容和数据。
- `Reviewer`（P1）：审核商品事实、品牌与合规。
- `Admin`：查看任务、成本、错误和审计日志，不直接修改用户内容。

### 2.2 核心用户故事

- 作为创作者，我想导入商品图片和卖点并保存为 SKU，以便以后不再重复描述商品。
- 作为创作者，我想让系统给出三个有区别的种草角度，以便快速比较表达方式。
- 作为创作者，我想用多张商品参考图生成真人手持生活方式图，同时保持杯型、材质和花纹一致。
- 作为创作者，我想从一张已选图片生成 5–15 秒轻动效/短视频，以便适配不同平台形式。
- 作为创作者，我想在发布前查看商品一致性、敏感词、版权和 AI 标识提醒，以降低违规风险。
- 作为创作者，我想将标题、正文、标签、封面和素材一起导出或发布，减少手工搬运。
- 作为创作者，我想看到某个 SKU 的不同内容版本表现，以便决定下一条内容。
- 作为创作者，我想让评论洞察生成新的提示词建议，但由我确认后才使用。

## 5. 端到端流程

### 5.1 主流程

1. 用户新建 SKU，上传商品主图/细节图或粘贴链接。
2. 系统抽取标题、类目、规格、材质、颜色、价格、卖点和禁用表达。
3. 用户逐项确认，无法确定的字段保持 `needs_confirmation`，模型不能自行补全事实。
4. 用户选择目标平台、目标人群和内容目标。
5. 系统生成三个创意角度，每个角度显示要改变的变量和理由。
6. 用户选择角度和候选数，确认预计额度、成本区间和耗时。
7. 系统异步生成图片，完成后进入人工审核。
8. 用户可采用图片、派生短视频/轻动效，或仅修改一个变量重试。
9. 系统生成标题、正文、标签、CTA 和披露语候选。
10. 用户完成商品一致性、平台规范、版权和表达合规确认。
11. 用户导出/系统分享；若已获得平台官方权限，则在二次确认后发布。
12. 系统绑定平台帖子 ID 或用户回填的帖子 URL。
13. 系统同步或导入指标，按 SKU/版本展示表现。
14. 评论聚类和表现分析形成新的创意建议，用户确认后创建实验。

### 5.2 发布降级链

```text
官方 OAuth + 发布 API（已审批）
  ↓ 不可用/权限不足
系统分享或唤起平台 App
  ↓ 无回执
导出内容包 + 用户手动发布 + 回填 URL
```

三个结果状态必须分开：`已导出`、`待用户确认发布`、`平台已确认发布`。

## 6. 详细功能需求

### FR-01 SKU 导入与事实卡（P0）

输入：商品图片、商品链接、CSV/表格字段。

处理：抽取可见/已有事实，标记来源与置信度。

输出：`SKU` 与不可变的 `ProductSnapshot`。

约束：价格、容量、材质、功能功效不得由模型无依据补写。

验收：

- 同一 SKU 可关联多张原始图、细节图和参考场景图。
- 每个字段保存来源、更新时间、确认人和修改历史。
- 未确认的关键字段会阻止发布，但不阻止保存草稿。

### FR-02 品牌/账号画像（P0）

用户填写品牌调性、色彩、常用场景、目标人群、禁用元素和优秀参考内容。系统生成可编辑摘要。

验收：用户可以查看、修改、导出和删除画像；删除后不继续用于新任务；敏感推断不得自动写入画像。

### FR-03 创意简报与提示词版本（P0）

提示词拆为：商品事实、卖点、受众、场景、人物/手模、动作、构图、风格、光线、平台比例、CTA、负面约束。

验收：

- 每次生成保存 PromptVersion、模型、参数、参考图顺序、耗时、费用和结果。
- 用户能看到结构化摘要，而不必直接编辑底层提示词。
- 创建 A/B 时只允许选择一个主要变量变化。

### FR-04 图片生成（P0）

支持单 SKU 多参考图、批量候选、3:4/4:5/9:16 预设和异步任务。

验收：

- 任务刷新页面/切后台后可恢复。
- 每个候选可追溯到 SKU 快照、提示词版本和参考图。
- 系统显示排队、处理中、待审核、完成、失败、取消状态。
- 失败原因可操作；重试是否扣费在执行前明确显示。
- 用户必须确认杯型、材质、图案、规格和可见文字是否被改变。

### FR-05 视频与轻动效（P0 受限版）

从用户已采用的图片生成 5–15 秒循环 MP4/短视频，配置轻微镜头移动、产品动作、环境动态、字幕与音乐。

验收：

- 明确输出是 GIF、MP4 还是 Apple Live Photo，不混称。
- 视频继承对应 AssetVersion 和 SKU 快照。
- 比例、时长、文件体积、安全区和音频版权经过检查。
- 只有审核通过的视频可进入发布流程。

### FR-06 内容包与合规审核（P0）

内容包包含：有序素材、封面、标题、正文、标签、CTA、商品链接占位、广告/AI 披露语。

审核维度：商品一致性、未经证实的功效、价格/赠品、禁用词、肖像/素材版权、AI 标识、平台格式。

验收：每个问题给出定位、原因和修复动作；用户确认结果写入 ReviewDecision 和审计日志。

### FR-07 导出与发布（P0/P1）

P0：导出 ZIP/文件包、系统分享、复制文案、回填帖子 URL。

P1：经官方审批的 OAuth、内容上传、发布回执和状态查询。

验收：

- 发布前再次确认平台账号、SKU、内容、商品链接和披露语。
- 只有获得平台 `post_id` 或等价官方回执，状态才为 `published`。
- 请求超时时进入 `unknown`，不得自动重复发布；先查询平台状态。
- OAuth token 加密存储、最小 scope、支持撤销和过期提示。

### FR-08 数据与归因（P0/P1）

数据层级：平台 → 账号 → SKU → 内容版本 → 平台帖子 → 指标快照/归因事件。

验收：

- 所有指标标注平台、数据源、统计窗、同步时间和 `actual/estimated/manual` 类型。
- 导出不等于发布，发布不等于获得订单归因。
- 订单、GMV、佣金和退款仅在合法来源和明确口径下展示。
- 无内容到订单映射时仅展示相关性，不称“该内容带来销售”。

### FR-09 评论洞察（P1，MVP 支持手工导入）

评论来源为用户粘贴、CSV 或经授权 API；进行去标识化、主题聚类、疑问/喜欢点/异议/需求识别。

验收：每条洞察能回溯到匿名样本与时间窗；用户可排除错误样本；系统建议不得未经确认自动改变商品事实或发布内容。

### FR-10 A/B 创意实验（P0 受限版）

同一 SKU 仅改变一个主要变量：首图、场景、Hook、标题、标签、CTA 或发布时间。

验收：

- 实验创建时定义假设、主指标、观察窗、最低样本和停止规则。
- 数据不足时显示 `insufficient_data`，不得宣布赢家。
- 结果展示账号、时间、自然流量差异等混杂因素。
- 胜出方案复用前仍需用户确认。

## 7. 状态机

| 对象 | 状态 |
|---|---|
| SKU | `draft → needs_confirmation → active → paused/archived` |
| 生成任务 | `queued → processing → needs_review → ready / failed / cancelled` |
| 审核 | `pending → approved / changes_requested / rejected` |
| 发布 | `draft → scheduled → publishing → published / failed / unknown / deleted` |
| 数据同步 | `not_connected → syncing → current / delayed / partial / error` |
| 实验 | `draft → running → insufficient_data → concluded / stopped / archived` |

## 8. 数据模型

```text
Workspace
├─ User / Membership
├─ ChannelAccount / OAuthGrant
├─ BrandProfile / AudienceInsight
├─ SKU
│  ├─ ProductSnapshot
│  ├─ SourceAsset
│  └─ Campaign
│     ├─ CreativeBrief
│     ├─ PromptVersion
│     ├─ GenerationJob
│     ├─ AssetVersion
│     ├─ ReviewDecision
│     └─ PublishRecord ─ PlatformPost
│                         ├─ MetricSnapshot
│                         └─ AttributionEvent
├─ Experiment / ExperimentArm
├─ CostLedger / QuotaLedger
└─ AuditLog
```

关键约束：

- `AssetVersion` 必须引用 `product_snapshot_id`，避免商品更新后历史素材失去事实基线。
- `PublishRecord` 与 `PlatformPost` 分离，保留失败、超时和手工回填路径。
- `MetricSnapshot` 保存快照时间和来源，不能覆盖历史值。
- `PromptVersion` 和 `ReviewDecision` 不可静默修改，仅能创建新版本。

## 9. 权限、安全与合规

- OAuth 仅申请完成当前功能所需 scope，token 服务端加密，不落日志和客户端明文。
- 参考图、评论、订单和平台账号数据支持导出、删除、撤销授权和保留期配置。
- 多租户对象必须带 `workspace_id` 并实施行级隔离。
- 用户需确认真人/手模、声音、商标、图片和音乐的授权。
- 对 AI 生成内容、商业推广、联盟带货和商品功效按平台规则提供披露提醒。
- 禁止用 AI 虚构真实使用经历、价格优惠、疗效、权威背书或用户评价。

- SKU → 首个可审核候选 P50/P90。
- 候选采纳率、商品一致性通过率、返工次数。
- 单个采纳素材的总生成成本。
- 生成失败率、重试率、失败重复扣费率。
- 导出/发布率、帖子 ID/URL 绑定率、数据回流率。

## 11. MVP 上线门槛

- 完成 SKU → 图片候选 → 审核 → 内容包 → 导出 → URL 回填完整链路。
- 页面/进程中断后生成任务可恢复，重复请求幂等。
- 所有内容版本可追溯到商品快照、参考图、提示词和模型参数。
- 导出、发布中、已发布、未知和失败状态准确区分。
- 未经用户确认不能发布或自动改变商品事实。
- 所有数据展示均标明来源和更新时间。
- 完成隐私删除、授权撤销、素材权限和审计日志测试。

## 12. 里程碑建议

### MVP：验证内容生产闭环

SKU 入库、图片候选、一种轻动效、内容包、人工审核、导出/分享、数据回填、基础实验。

### P1：验证单平台自动化

优先验证抖音官方 OAuth、授权账号投稿和已获准的内容基础数据；所有能力仍以应用审核和实际 scope 为准。小红书先接电商开放平台中实际获批的店铺/商品/订单能力，普通创作者笔记自动发布、评论和内容归因在没有官方权限证据前不进入 P1 验收。同步加入团队审核和视频模板。

### P2：形成数据壁垒

多平台适配、多账号、动态画像、受约束自动优化、订单归因、数字人和机构协作。
