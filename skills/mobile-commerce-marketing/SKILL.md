# 移动端电商营销

围绕“在手机上更快找到值得测试的商品，并持续产出能带来点击和成交的内容”设计营销系统。所有方案都要同时说明用户动作、系统自动化、平台约束和可观测指标。

## 核心闭环

1. **发现**：按地区、类目、价格、佣金、需求趋势、竞争度和内容供给筛选商品；解释推荐原因。
2. **决策**：展示预估收益、风险、样本/库存、商品链接和可测试角度，让用户能在移动端快速收藏或开始创作。
3. **创作**：把商品上下文带入角度、脚本、素材、数字人/无脸视频、语音、字幕和 CTA，支持多版本实验。
4. **发布**：校验商品链接、披露/平台政策、封面、字幕、标签和发布时间；发布前提供可撤回的预览和错误修复。
5. **归因**：把内容 ID、商品 ID、店铺/账号、渠道、点击、加购、订单、GMV、佣金和成本关联起来。
6. **复盘**：按商品、创意角度、开头、时长、声音、发布时间和受众切片，给出下一步“保留 / 迭代 / 停止”建议。

## 移动端设计规则

- 首屏只服务一个主任务；发现、创建、分析可以用底部导航，但“创建”必须携带商品上下文。
- 为联网、生成、审核、发布、额度耗尽、权限失效和无数据分别设计状态，不用空白页代替状态。
- 把高成本操作（视频生成、发布、授权店铺、上传素材）拆成可恢复任务，显示进度、耗时、失败原因和重试。
- 所有收益数字标注口径、时间窗、货币和“估算/实际”状态；不能暗示收益保证。
- 关键按钮使用图标 + 短文本，支持单手操作、动态字体、深色模式、低网速和无障碍标签。
- 不在未获授权时索取或发送店铺凭证、私人照片、联系人或支付信息。

## 指标树

先定义北极星指标，再拆成可行动的前置指标：

`有效内容带来的归因佣金/GMV`
→ 内容发布率 → 观看质量（3 秒留存、完播、互动） → 商品点击率 → 加购率 → 成交率 → 佣金率

同时监控生成成功率、首稿到发布耗时、每条内容成本、重复创作率、7/30 日留存、权限失败率和违规率。公式和事件命名见 [metric-tree.md](references/metric-tree.md)。

## 实验方法

- 一次只改变一个主要变量（商品、开头、角度、时长、声音、CTA 或发布时间）。
- 先用小样本验证“能否发布”和“是否被看”，再扩大到成交/佣金结论。
- 对冷启动用户提供默认角度和示例商品，但允许查看推荐依据并反馈“不适合我”。
- 把失败原因结构化：素材不足、模型失败、政策风险、权限失效、链接失效、平台限流、真实低转化。
- 任何“AI 预测会卖”的文案都改成概率/估算/历史信号，并保留人工复核。

需要做 KPI、埋点或实验方案时，先读取参考文件，再产出事件表、漏斗、实验假设和停止条件。
