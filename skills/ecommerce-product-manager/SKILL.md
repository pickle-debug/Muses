# 电商软件产品经理

以用户任务和可验证结果为中心，把“想做一个类似产品”收敛为分阶段可交付的产品定义。默认假设平台政策、店铺授权、AI 成本和归因口径都是一等约束。

## 需求工作流

1. **问题定义**：写目标角色、场景、触发、当前替代方案、痛点证据和成功结果；区分卖家、联盟创作者、机构和平台管理员。
2. **旅程与状态**：画主流程和异常流程，至少覆盖未连接店铺、商品失效、生成排队/失败、审核不通过、发布失败、指标延迟和额度耗尽。
3. **MVP 切片**：按“必须证明核心价值 / 可以人工兜底 / 明确延期”分层，不把 11 个 AI 专家全部首发。首版优先选择一个地区、一个平台、一个内容类型和一个归因口径。
4. **能力拆解**：把功能写成输入 → 处理 → 输出 → 状态 → 权限 → 成本 → 指标。对 AI 能力补充模型、版本、提示词、回退、审核和人工覆核。
5. **数据契约**：定义用户、店铺、账号、商品、创作任务、素材、视频版本、发布记录、内容指标、订单归因、额度/计费和审计日志的 ID 关系。
6. **验收与上线**：每条需求有 Given/When/Then、埋点、错误码、权限矩阵、回滚方案和人工操作手册；先做小流量灰度和成本上限。

## 首版产品建议

对“类似 Moras”的产品，先验证一条窄闭环：

`导入/粘贴商品 → 生成 1 个可审视频 → 用户确认 → 发布或导出 → 回收基础播放/点击数据`

选品大盘、数字人、多模型路由、自动发布、收益预测和多平台扩展应按证据逐步加入；不要在没有真实归因数据前承诺“爆款”或“保证收益”。

## PRD 最低要求

- 用户故事与非目标。
- 页面/入口和导航关系。
- 状态机和可恢复任务。
- API/事件/字段与数据保留策略。
- 额度、成本、计费和配额规则。
- 平台 OAuth/权限范围、令牌加密、撤销和审计。
- 内容政策、AI 披露、版权和用户内容所有权边界。
- 指标口径、实验设计和上线门槛。

使用模板时读取 [prd-template.md](references/prd-template.md)。

## 评审原则

- 先评审“是否解决真实任务”，再评审“是否像竞品”。
- 优先减少从商品到发布的手工交接；不要只增加更多生成按钮。
- 收益预测必须可解释、可追溯、有时间窗，并与真实结果分栏。
- 对任何外部副作用（发布、授权、上传、付款）提供明确确认和失败恢复。
- 保持平台适配层与核心领域模型分离，避免把 TikTok 字段散落在所有页面和服务中。
